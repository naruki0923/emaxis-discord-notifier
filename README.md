# eMAXIS Slim 保有資産 Discord通知

保有している eMAXIS Slim の評価額と前営業日比を、毎朝8時（JST）にDiscordへ通知します。土日・祝日も実行され、その時点で公表済みの直近営業日の値を使います。

対象の銘柄:

| 表示名 | ファンド | ISIN | 協会コード |
| --- | --- | --- | --- |
| S＆P500 | eMAXIS Slim 米国株式（S&P500） | JP90C000GKC6 | 03311187 |
| オルカン | eMAXIS Slim 全世界株式（オール・カントリー） | JP90C000H1T1 | 0331418A |

通知の例:

```
・資産
全体資産：15,720円
S＆P500：10,727円
オルカン：4,993円

・前営業日比
S＆P500：+35円
オルカン：-7円

・損益
投資金額：17,000円
資産：15,720円
```

前営業日比は、基準価額の変化を保有口数に掛けた、あなたの保有分の増減です（基準日に約定した分は含みません）。投資金額は取得金額の合計です。

実行はGitHub Actions上で行うため、Macの電源やスリープ状態に関係なく通知が届きます。

## 設定（初回のみ）

1. Discordで通知先チャンネルを開き、`チャンネルの編集` → `連携サービス` → `ウェブフック` → `新しいウェブフック` を選び、`ウェブフックURLをコピー` します。
2. GitHubのプライベートリポジトリにこのフォルダをpushします。
3. Webhook URLをSecretに登録し、銘柄ごとに保有内容を登録します。

```sh
gh secret set DISCORD_WEBHOOK_URL
./update.sh sp500 <保有口数> <取得金額> --monthly <積立金額> --day <積立日>
./update.sh オルカン <保有口数> <取得金額> --monthly <積立金額> --day <積立日>
```

保有情報はリポジトリに含めず、Secret `PORTFOLIO_JSON` とローカルの `portfolio.json`（`.gitignore` 済み）だけに保存します。Secretは後から読み出せないため、`update.sh` は手元の `portfolio.json` を正として全銘柄分をまとめてSecretへ書き込みます。`update.sh` は同じMac（同じ `portfolio.json`）から実行してください。

## 保有口数・取得金額の更新

SBI証券の最新表示の値を、銘柄ごとにそのまま渡します。桁区切りのカンマや「口」「円」は付いていても構いません。

```sh
./update.sh sp500 2,402 12,000
./update.sh オルカン 1,320 5,000
```

銘柄は `sp500` / `オルカン`（`allcountry` でも可）で指定します。積立の設定（`--monthly` / `--day`）は一度指定すれば、次回以降の更新でも引き継がれます。積立をやめたときは `--monthly 0` を指定します。

更新後の内容をその場で表示します。反映は次回の朝8時の通知からです。すぐにDiscordへ送って確認したい場合は `--notify` を付けます。

## 単発で買ったとき

SBI証券の表示に反映される前（約定前）でも、`--buy` で注文額を登録しておくと約定後に推定で加算します。SBI証券の表示値はその時点のものをそのまま渡します。

```sh
./update.sh オルカン 0 0 --buy 10,000
```

注文日は実行した日として扱います。15時以降の注文など、受付日が翌営業日になった場合は1営業日ずれます。SBI証券の表示に反映されたら、その値で `update.sh` を実行し直してください。

## 積立の自動反映（推定）

積立を設定すると、`update.sh` で登録した日より後の積立を自動で保有内容に加えます。

- 取得金額: 1回ごとに積立金額を加算
- 保有口数: 積立日（休日なら翌営業日）に注文し、その翌営業日の基準価額で約定したものとして `積立金額 ÷ 基準価額 × 1万口`（端数切り捨て）を加算

SBI証券にはログインしません。投資信託協会が公開している基準価額から計算しているため、実際の口数と数口ずれることがあります。ずれが気になったら、SBI証券の表示値で `update.sh` を実行し直してください。その時点の値が新しい起点になります。

`./update.sh` 実行時や `python3 notifier.py --dry-run` では、加算した積立の約定日・金額・口数も表示します。

## 手動実行と確認

今すぐ通知を送る場合:

```sh
gh workflow run notify.yml
```

実行結果とログはGitHubの `Actions` タブ、またはターミナルで確認できます。

```sh
gh run list --workflow=notify.yml
```

## 手元での確認

Discordへ送らず取得結果と通知文だけを見る場合:

```sh
python3 notifier.py --dry-run
```

保有情報は環境変数 `PORTFOLIO_JSON`、なければ `portfolio.json` から読みます。S&P500だけだった頃のSecret（`PORTFOLIO_UNITS` / `PORTFOLIO_ACQUISITION_AMOUNT`）は、`PORTFOLIO_JSON` が無いときだけS&P500の保有として使われます。

## 停止

`.github/workflows/notify.yml` の `schedule` 行を削除してpushするか、GitHubの `Actions` タブでワークフローを `Disable` します。

## データの取得先

三菱UFJアセットマネジメントの公式APIは国外・データセンターのIPからのアクセスを403で拒否するため、GitHub Actions上では投資信託協会の「投信総合検索ライブラリー」の公開データを使います。手元のMacから実行した場合は公式APIが使われ、失敗したときだけ投資信託協会へ切り替わります。積立の推定に使う過去の基準価額は、常に投資信託協会から取得します。その回に使った取得先と基準日は `python3 notifier.py --dry-run` で確認できます。

## 注意

- 通知時刻はJSTの8:00ですが、GitHub Actionsのスケジュール実行は混雑時に遅れます。実績では1〜3時間程度遅れる日があります。
- 投資信託協会のデータは公式サイトより反映が遅く、基準日が1営業日前になることがあります。
- 基準価額は1万口あたりです。評価額と前営業日比は、基準価額×保有口数÷1万で計算し、1円未満を四捨五入しています。
- 1銘柄の取得に失敗しても、残りの銘柄で通知します（失敗した銘柄は「取得できませんでした」と表示し、Actionsの実行は失敗扱いになります）。
- この通知は情報提供のみを目的とし、投資助言ではありません。

## 付録: Mac上で動かす場合

`setup.sh` / `uninstall.sh` はmacOSのlaunchd（LaunchAgent）で動かすための旧構成です。Webhook URLはキーチェーン、保有情報は `portfolio.json` から読みます。Macが起動している間だけ通知されます。
